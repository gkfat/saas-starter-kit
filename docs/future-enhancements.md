## 會員條碼加上時效性機制

**現況**：`apps/liff` 會員卡（`apps/liff/src/components/AppHeader.vue`）的 QRCode 目前直接編碼未簽章的原始 `memberNo` 明文（見 `add-member-number` change）。這組編號本身不會變，只要被截圖或轉傳，任何人都能拿著同一張圖冒充該會員——目前可以接受，是因為店家端的掃碼核銷/查詢介面本來就還沒開發（`add-member-number` proposal 明確排除在範圍外），沒有實際被冒用的場景。

**未來方向**：若店家端掃碼核銷功能真的要開發，屆時應該一併導入具時效性的動態碼機制，例如：

- QRCode 內容改成「`memberNo` + 短時效 timestamp/nonce，由後端簽章」的字串，設定短 TTL（例如 30–60 秒）過期即失效，前端定期重新跟後端換發新的簽章碼並重繪 QRCode
- 或參考 TOTP（Time-based One-Time Password）類似機制，前後端各自依相同演算法與時間窗算出可驗證的動態碼，不需要每次都打 API 換發

兩種做法都需要新增對應的後端簽發/驗證邏輯，且必須跟店家端掃碼核銷介面（同樣是未來範圍）一起設計，才能確定實際的驗證流程與可接受的時效窗口大小。

**觸發時機**：待店家掃碼核銷/查詢介面真的要開發時，作為該次 change 的一部分一併處理，避免現在沒有實際使用場景就過早設計。
